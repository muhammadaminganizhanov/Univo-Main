## Аудит текущей `/ru/ecosystem` (браузер, 1440 / 390; EN и KY проверены)

Текущая страница: Карта (линия с «подвесами») → TECH (белый, сетка 8 ячеек) → PRODUCTION (Ink,
Сценарий → Съёмка → Монтаж) → Продукты (RETAIL: поток + реестр; SLOT: полоса слотов + сетка) →
«Как части работают вместе» (лестница из 5 шагов) → EndCta + большой футер. Высота 1440 ≈ 5960 px,
390 ≈ 7090 px. KY — тот же русский текст (перевод не готов), EN длиннее на 1–2 строки в местах.

### A. Что работает хорошо
- Сама идея «одна линия от UNIVO, части стоят на ней» и пунктирное продолжение для следующей части.
- Точные, проверенные тексты: роли, описания, scope, сегменты SLOT, шаги PRODUCTION.
- Разные ссылки по реальному состоянию: внешний URL → отдельный сайт; продукт без URL → ранний
  доступ; направление без URL → якорь на странице / форма с выбранным направлением.
- Цвет сущностей уже используется как точка, а не заливка. Без горизонтального скролла.

### B. Что слабее новой главной
- Hero: крупный заголовок + абзац + тонкая «вешалка» с узлами — схема мелкая, плоская, без весов;
  иерархия UNIVO → тип → часть читается только по скобкам «Направления / Продукты» над линией.
- Нет поведения: hover меняет только цвет текста; путь от UNIVO к части не показан.
- Секции не продолжают визуальный язык главной (вес линии по рангу, узлы на линии, ровный motion).
- Футер — старая большая композиция с гигантским логотипом.

### C. Что повторяет главную и здесь лишнее
- «Как части работают вместе» (вход → маршрут → профессии → ответственный → проект) — это та же
  история, что «Одна точка входа» на главной, только списком.
- EndCta с линией «кольцо → кнопка» повторяет общий финал без своей роли на этой странице.

### D. Таблицы / карточки / техдокументация вместо премиального сайта
- TECH: сетка 2×4 с номерами 01–08 и рамками — прайс-лист.
- Шапка профилей: `Тип / Статус / Рынок` как поля `dl` — карточка CRM.
- RETAIL: «Контроль бизнеса» — нумерованный реестр с линейками; SLOT: «Из чего состоит» — таблица 3×2.
- Легенда «Работает / Готовится к запуску» под картой — служебная подпись.

### E. Где нарушена иерархия
- В hero `UNIVO` и `PRODUCTION` набраны одним кеглем — мастер-бренд не главнее части.
- PRODUCTION на Ink с огромными «Сценарий / Съёмка / Монтаж» громче TECH и громче продуктов, хотя это
  равные направления.
- Заголовок «Собственные продукты» тише, чем лиды и шаги ниже; синие/голубые линейки-разделители
  длиной во всю ширину — цвет как заливка, не как сигнал.

### F. Где плохо читается структура группы
- Тип (направление / продукт) — подпись в скобке, а не уровень структуры.
- Разница «направления работают над задачей / продукты — системы, которыми пользуются» нигде не
  показана формой: профили и продукты собраны одинаково (идентичность слева, список справа).
- То, что TECH и PRODUCTION могут работать вместе, сказано только в лестнице текстом.
- Общий стандарт работы на странице отсутствует вовсе.
- Что каждая часть — отдельный сайт, видно только по иконке ↗ на кнопке.

### G. Что сохранить
- Проверенный контент (`@univo/content`, словари) и логику ссылок `resolveEntityLink()` /
  `getEcosystemUrl()`; early-access для RETAIL и SLOT; якоря `#tech`, `#production`, `#retail`, `#slot`.
- Шаги PRODUCTION, поток RETAIL «Склад → Остатки → Филиалы → Продажи», абстрактный день SLOT.
- Пунктир следующей части.

### H. Что пересобрать полностью
- Hero + карта → **Master map** с уровнями, весами и состояниями.
- Профили TECH / PRODUCTION → одна секция **Направления**: открытые рабочие линии + «вместе».
- Продукты → **замкнутые контуры** (operating loop) вместо реестров и таблиц.
- «Как части работают вместе» → убрать; смысл перенесён в «вместе» и финал.
- Новый компактный слой **общего стандарта**.
- Финал страницы + компактный футер (как на главной, без её подписи-символа).

## Концепция — «Одна группа. Разные роли внутри системы»

Страница — подробный architectural view той же системы, что на главной. Одна грамматика: линия,
узел, вес по рангу, цвет только как сигнал. Но у каждой роли своя **форма линии**, и эта форма
объясняет роль без абзацев:

| Роль | Форма | Почему |
|---|---|---|
| UNIVO | точка Tangerine + несущая ось | исходная точка всего |
| Тип (направления / продукты) | уровень: ветка от оси со своим весом | группа делится сначала по типу |
| Направление | **открытая линия**: задача входит → работа → результат выходит | работают над задачей клиента |
| Продукт | **замкнутый контур** | система, которой бизнес пользуется каждый день |
| Стандарт | **общая связка**, через которую проходят все линии | связаны не только именем |
| Следующая часть | пунктир той же оси | новая часть встаёт в ту же архитектуру |

Контур продукта — это *u* и *n* словесного знака, сомкнутые в один цикл (повороты только
полукругами), то есть та же геометрия, что у арок главной.

## Визуальная иерархия

- Display — только в hero: «Экосистема UNIVO» (H1, крупно) и под ним утверждение
  «Одно имя. Разные роли внутри группы.». Секции — h2 statement-размера, подписи малые.
- Вес линий по рангу (как на главной): ось UNIVO > ветка направлений > ветка продуктов > пунктир.
- Узлы: направления — заполненные (работают), продукты — кольца (готовятся к запуску), следующая
  часть — пунктирное кольцо. Легенда не нужна: статус написан словами у роли.
- Цвет сущности — только на узле, на коротком следе пути при hover/focus, на точке lockup.

## Signature moments

1. **Master map (hero).** Ось вниз от точки UNIVO. От неё две ветки-уровня — «Направления» и
   «Продукты» (подписи уровня на самой ветке, с пояснением). На ветках — части. Ось уходит пунктиром
   в «Следующую часть группы». Справа — панель-«ответ»: по умолчанию UNIVO (мастер-бренд), при
   hover/focus — роль части, описание, статус и куда ведёт ссылка (отдельный сайт ↗ / ранний доступ /
   «сайт направления готовится»).
2. **Открытые линии направлений.** TECH: задача → TECH → результат (что делает). PRODUCTION:
   задача → сценарий → съёмка → монтаж → результат (форматы). Затем «вместе»: одна задача
   расходится на TECH и PRODUCTION и сходится в один проект («Сайт и ролик к открытию филиала»).
3. **Контуры продуктов.** RETAIL: контур, по которому идёт товар (Склад → Остатки → Филиалы → Продажи
   → снова склад), внутри — «Контроль бизнеса». SLOT: контур дня, разделённый на слоты (запись /
   свободно), внутри — из чего состоит. Никаких фейковых интерфейсов.
4. **Связка стандарта.** Пять линий (четыре части + пунктир следующей) собираются в один жгут;
   пять стандартов — пять «скоб» на жгуте, у каждой название и проверка.

## Desktop (≥ 1024)

- Hero: заголовок слева сверху, лид справа; карта на 8 колонок, панель-ответ на 4 колонки.
  Вся первая сцена ≈ одна высота экрана 1440 × 900.
- Hover/focus по части: UNIVO отвечает (кольцо) → путь от UNIVO по оси и ветке рисуется цветом части
  → узел увеличивается → панель меняется → стрелка ↗/→ сдвигается. Остальные части ≈ 50 %.
- Клавиатура: части — ссылки; `:focus-visible` даёт то же состояние, что hover.
- Направления: слева идентичность (lockup, роль, описание, рынок, ссылка), справа линия.
- Продукты: слева идентичность, справа контур.
- Стандарт: жгут по горизонтали, пять скоб по ширине.

## Mobile (< 1024; отдельно 390 / 375 / 360 / 320)

- Карта — вертикальная система из HTML и CSS-линий: ось UNIVO слева, под ней два уровня со своими
  подспинами, части с цветными узлами, ролью и статусом видны сразу (без hover), пунктир следующей
  части в конце. Панель-ответ не показывается — всё уже написано у узлов.
- Линии направлений — вертикальные; «вместе» — своя вертикальная схема.
- Контуры продуктов — та же форма, уменьшенная по ширине; подписи модулей уходят под контур.
- Жгут стандарта — вертикальный слева, стандарты справа от скоб.
- Тап-цели ≥ 40 px, длинные имена (PRODUCTION) не ломают строку, `scroll-margin-top` под sticky header.

## Motion plan (CSS + SVG, без библиотек; тайминги главной)

| Сцена | Вход (`html.motion`, один раз) | Взаимодействие | Reduced motion |
|---|---|---|---|
| Master map | точка UNIVO → ось рисуется вниз → ветки уровней → узлы по порядку → подписи (≈ 1 с) | hover/focus: ответ UNIVO 220 ms → путь 600–900 ms → узел → панель → стрелка | финальная схема сразу |
| Направления | каждая линия рисуется от задачи к результату, узлы шагов по очереди (stagger 90 ms) | — | сразу |
| Вместе | одна задача → расхождение → два узла → схождение → проект | — | сразу |
| Продукты | контур рисуется один раз по кругу, узлы/слоты зажигаются по ходу; потом покой | — | сразу |
| Стандарт | жгут рисуется, скобы смыкаются по очереди | — | сразу |
| Финал | заголовок из маски (`data-reveal`), линия к точке UNIVO | — | сразу |

Никаких бесконечных анимаций, пульсаций будущего узла, параллакса, scroll hijacking и пружин.

## Технически

- Все секции — server components; состояние hover/focus — CSS `:has()` с генерируемыми правилами
  (как на главной). Нет новой клиентской JS-логики и зависимостей.
- Ссылки — только через `resolveEntityLink()` (внутри — `getEcosystemUrl()`).
- Компактный футер главной включён и для этой страницы тем же селектором (`data-scene`), другие
  страницы не затронуты.
- Тексты: только существующие проверенные формулировки; новые ключи словаря — перестановка
  существующих смыслов (RU/EN синхронно, KY наследует RU, как сейчас).
